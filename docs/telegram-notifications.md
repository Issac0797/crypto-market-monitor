# Telegram 通知边界

Telegram 默认关闭，只有显式传入 `--telegram` 才会加载凭据、验证 Bot 身份并启用发送。
通知队列、风险生命周期、HTML 转义模板和只读命令均由本项目独立维护。

默认发送：

- 风险首次触发
- 风险升级
- 风险恢复
- 用户主动查询的只读回复

数据不可用、数据恢复和价格窗口重新预热默认只写健康快照和日志，不进入 Telegram。
显式添加 `--data-notifications` 后才发送这些运维诊断。

## 目的地与命令

- 默认目的地必须等于绑定 Chat ID，且在允许列表中。
- 只响应绑定 Chat ID 发来的新消息；群聊成员可发起查询。
- `/status`、`/risks`、`/history`、`/settings` 只读。
- 不支持启停服务、改配置、触发交易、下单或远程执行。

## 投递保证

发送队列持久化，失败有有限重试、指数退避和 Telegram 429 的 `retry_after` 处理。
普通同类消息可以合并，严重消息不等待合并。旧事件不会被无限补发。

Telegram 服务端确认成功与本机记录 `sent` 之间崩溃时仍可能重复一条消息。
Telegram Bot API 没有业务幂等键，因此项目不承诺端到端恰好一次。

## 单轮询所有者

同一 Bot Token 只能有一个 `getUpdates` 所有者。启用命令行查询时，不要同时运行：

- 第二个 `risk_watch_cli --telegram`
- 独立 `bot_cli --once`
- 另一个调试轮询器
- 另一台使用同一 Token 的服务

409 冲突应停止其他实例，而不是持续争抢或删除锁文件。

完整的创建、Chat ID 获取、验证和测试步骤见 [Telegram 配置](bot-setup.md)。
